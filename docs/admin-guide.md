# 管理员指南 / Руководство администратора

## 管理职责 / Обязанности администратора

管理员负责维护 `main` 分支、检查 Pull Request（PR）并在自动检查通过后合并。提交和 PR 必须来自实际贡献者的账号；管理员不代替其他成员提交。
Администратор поддерживает ветку `main`, проверяет Pull Request (PR) и объединяет его после успешных автоматических проверок. Коммиты и PR должны создаваться из аккаунта фактического автора; администратор не отправляет изменения от имени другого участника.

合并前确认 PR 只包含任务范围内的文件、目标分支为 `main`，并且修改说明清楚。
Перед объединением нужно убедиться, что PR содержит только файлы текущей задачи, целевая ветка — `main`, а описание изменений понятно.

## 文件检查 / Проверка файлов

```sh
python -B -X utf8 tools/check_docs.py
git diff --check
```

文档使用相对链接，图像保存在 docs/images。移动文件时同步修改引用。
Документы используют относительные ссылки; изображения хранятся в docs/images. При переносе файла обновляются ссылки.

## 代码检查 / Проверка кода

```sh
python -B -m unittest discover -s tests -v
python -m pytest -q
flake8 bookclub tests tools --count --select=E9,F63,F7,F82 --show-source --statistics
```

修改前查看 git status 和 git diff，提交时选择本次修改的文件。
Перед изменениями проверяются git status и git diff; в коммит включаются файлы текущей правки.

## Pull Request 审核与合并 / Проверка и объединение Pull Request

1. 打开 PR，确认源分支属于贡献者，目标分支是 `main`。

   Открыть PR и проверить, что исходная ветка принадлежит автору, а целевая ветка — `main`.
2. 查看 **Files changed**，按照[审查清单](review-checklist.md)检查内容，不批准超出任务范围的修改。

   В разделе **Files changed** проверить изменения по [чек-листу ревью](review-checklist.md) и не одобрять изменения вне задачи.
3. 等待 GitHub Actions 中的 pytest、flake8 和文档检查全部通过。

   Дождаться успешного завершения pytest, flake8 и проверки документации в GitHub Actions.
4. 由另一名成员完成审核；有问题时请求修改，修复后重新检查。

   Ревью выполняет другой участник; при наличии замечаний запрашиваются исправления и проводится повторная проверка.
5. 审核与自动检查都通过后合并 PR，并删除已合并的功能分支。

   После одобрения и успешных проверок объединить PR и удалить объединённую рабочую ветку.

合并后同步本地 `main`：
После объединения обновить локальную ветку `main`:

```sh
git switch main
git pull --ff-only origin main
```

## 保存与恢复 / Сохранение и восстановление

文件保存规则见 [STORAGE_POLICY.md](../STORAGE_POLICY.md)，协作命令见 [COLLABORATION.md](../COLLABORATION.md)。
Правила хранения приведены в [STORAGE_POLICY.md](../STORAGE_POLICY.md), команды совместной работы — в [COLLABORATION.md](../COLLABORATION.md).

恢复前保存当前修改的补丁或副本，再从指定提交恢复文件。已经推送或合并的提交使用 `git revert <commit>` 撤销，并通过新的 PR 合并回 `main`；不要重写共享分支历史。
Перед восстановлением сохраняется патч или копия текущих изменений. Уже отправленный или объединённый коммит отменяется командой `git revert <commit>`, а результат возвращается в `main` через новый PR; историю общей ветки переписывать нельзя.
