# 审查清单 / Чек-лист ревью

Сверять с [требованиями](review-requirements.md) и [OpenAPI](../api/bookclub.openapi.yaml). Сначала читать тесты, затем реализацию. Отличать ошибки от предложений и вопросов.

## R1 需求与正确性 / Требования и корректность
- 去除首尾空白后再按 Unicode 码点计数，边界包含 10 和 1000。/ Удалять краевые пробелы до подсчёта кодовых точек; границы 10 и 1000 включены.
- 空值、类型错误和长度错误的优先级明确；状态规则符合需求。/ Порядок ошибок ввода и правила статусов соответствуют требованиям.

## R2 测试 / Тесты
- 覆盖 9、10、1000、1001、空值、类型、空白与 Unicode；验证返回值和错误码。/ Проверены границы, пустой ввод, тип, пробелы, Unicode, результат и код ошибки.
- 检查缺少的组合；区分本地运行结果和远程检查。/ Проверить недостающие сочетания; различать локальные тесты и проверки GitHub.

## R3 API 契约 / Контракт API
- 字段类型、必填规则、长度与错误码一致；区分请求和响应。/ Согласованы типы, обязательность, длина и коды; запросы отделены от ответов.
- 保留现有接口及其参数、响应定义。/ Сохранены исходные API, их параметры и определения ответов.

## R4 可维护性 / Сопровождение
- 名称清楚，边界值和错误码容易同步修改，不增加无用依赖。/ Понятны имена; ограничения и коды легко согласовать; нет лишних зависимостей.

## R5 文档 / Документация
- 函数说明包含返回值及异常约定；PR 说明与实际改动、测试结果一致。/ Описаны результат и исключения; описание PR соответствует изменениям и проверкам.

## R6 安全与资源 / Безопасность и ресурсы
- 异常不泄露用户原文；外部输入在服务入口设置合理大小限制。/ Исключения не раскрывают ввод; размер внешних запросов ограничивается на входе сервиса.

评论带上类别 R1–R6 及性质：`fix`（缺陷 / ошибка）、`suggestion`（建议 / предложение）、`question`（问题 / вопрос）或 `follow-up`（后续 / позже）。说明位置、观察、影响和建议。
В комментарии указать раздел, метку, место, наблюдение, влияние и предложение.
