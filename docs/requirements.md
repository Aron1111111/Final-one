# 需求摘要 / Сводка требований

REQ-01 参与者可以查看活动列表。GET /meetings 的 limit 为 1–100，默认 20；offset 不小于 0，默认 0。空列表返回 200 和 []。
REQ-01 Участник просматривает встречи. limit от 1 до 100, по умолчанию 20; offset от 0, по умолчанию 0. Пустой список возвращает 200 и [].

REQ-02 已登录参与者可以报名活动，身份来自 Bearer 令牌，不通过请求体传入参与者编号。
REQ-02 Вошедший участник записывается на встречу; пользователь определяется по Bearer токену, тело запроса не нужно.

REQ-03 成功创建报名返回 201；活动不存在返回 404；重复报名返回 409。缺失或无效令牌返回 401。
REQ-03 Создание записи возвращает 201, отсутствие встречи — 404, повторная запись — 409, неверный или отсутствующий токен — 401.

REQ-04 数据库使用 meeting_id 与 member_id 唯一约束。先提交报名事务，再安排邮件提醒；提醒失败不撤销已经成功的报名。
REQ-04 Уникальность пары meeting_id и member_id исключает дубли. После фиксации записи планируется письмо; сбой напоминания не отменяет запись.

REQ-05 组织者权限由后端校验；普通参与者不能以组织者身份添加图书或创建活动。
REQ-05 Сервер проверяет роль организатора; обычный участник не может создавать встречи или добавлять книги от его имени.

REQ-06 活动描述去掉首尾空白后，长度为 10–1000 个 Unicode 码点。
REQ-06 После удаления краевых пробелов описание содержит 10–1000 кодовых точек Unicode.

REQ-07 活动状态仅由组织者修改；转换规则及错误码见[描述与状态规则](review-requirements.md)。
REQ-07 Статус меняет только организатор; переходы и коды приведены в [правилах](review-requirements.md).
